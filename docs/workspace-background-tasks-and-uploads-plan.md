# 工作区后台任务与附件上传实施计划

日期：2026-10-22。状态：**已实现并完成构建验证，设备验收待进行**。

当前代码基线：`61cd5833`。本计划覆盖两个独立任务：本地工作区后台命令、聊天附件统一上传。调研依据见 [后台任务源码调研](background-tasks-source-survey.md)。

## 1. 交付目标与范围

| 任务 | 用户最终可以做什么 |
| --- | --- |
| 后台任务 | 把长命令转后台，继续聊天、切换页面，随时查看日志和停止；完成结果回到原会话 |
| 附件上传 | 直接从聊天上传任意类型的文件；图片同时供模型看图和工作区工具处理，不再手动导入第二次 |

- 本轮执行环境以现有本地 PRoot 工作区为范围，保留现有 rootfs 和 `/upload` 挂载方式。
- Android 与 Web 的附件入口一起调整；后台任务的共享服务、状态展示和停止操作保持同一套语义。
- SSH 工作区本轮不增加远程后台管理或自动 SFTP 上传；不得将本机 `/upload` 路径宣称为远端可访问路径。
- 不增加自主子 Agent、定时任务、重启后自动重跑命令或新的容器运行时。
- 沿用 Material 3 Expressive。根据最终确认，任务 UI 直接放在聊天窗口内、输入框上方；沿用现有圆角、色彩、字重和工具详情样式。

## 3. 任务一：本地工作区后台任务

### 3.1 任务保留规则

| 操作或事件 | 约定行为 |
| --- | --- |
| 普通 shell 调用 | 仍在前台等待，不自动转后台 |
| 模型传入 `background: true` | 启动后返回 taskId 和日志信息，由管理器继续持有进程 |
| 用户点击“转后台” | 解除这次工具等待，同一命令、同一进程继续运行，不重复执行 |
| AI 本轮结束、离开页面、切换会话 | 后台任务继续，所属会话、工作区和 cwd 保持启动时的绑定 |
| 修改聊天的工作区设置 | 不把已运行任务迁移到新工作区；原任务仍可在管理界面查看和停止 |
| 切换消息分支 | 保留任务和来源记录；完成结果不自动续写无关分支 |
| 返回桌面或锁屏 | 通过独立前台服务托管，显示运行任务通知；处理系统限制和中断 |
| 点击“停止生成” | 停止本轮前台执行，暂停会话自动继续；已明确转后台的任务保留 |
| 单独停止任务 | 终止对应进程及受管理的子进程，记录停止状态 |
| 删除会话、删除工作区、重装 rootfs | 先阻止新任务进入并停止相关任务，等清理完成后再删数据或替换文件 |
| App 被终止、强行停止或设备重启 | 不承诺原进程继续；下次启动将遗留运行记录标为中断，不自动重跑 |

正常后台完成可以唤醒原会话；用户主动停止生成后，结果只入队并更新任务状态，等用户继续聊天再处理，不能擅自解除暂停。

### 3.2 建议默认值（供本次审核）

| 项目 | 建议值 |
| --- | --- |
| 前台默认执行超时 | 保持现有 30 秒；显式正值先沿用现有 600 秒上限 |
| 后台默认执行超时 | 未指定或 `timeout: 0` 表示不设命令时限；显式正值生效，首版沿用 600 秒上限 |
| 前台手动转后台 | 移除默认 30 秒时限，保留模型显式指定的执行时限 |
| 等待/读日志 | 支持立即返回或最多等待 30 秒；等待超时只结束等待，不终止任务 |
| 并发 | 每会话最多 2 个、App 总计最多 4 个；启动中和停止中也占额度，超额直接返回可理解的错误 |
| 日志 | 每任务文件最多 20 MiB；到上限后标记截断并继续排空输出管道，保持有界尾部摘要，不因此杀任务 |
| 历史清理 | 已结束且结果已处理的任务日志保留 7 天；运行中及未投递结果不得被自动清理 |

“工具等多久”和“命令最多跑多久”分别管理，禁止用协程等待超时顺带取消底层后台任务。

### 3.3 实现分层

1. **受管理进程层**：在 `workspace` 模块扩展现有启动链路，暴露进程标识、输出、等待和终止操作。保留 `--kill-on-exit`，工具返回后由管理器保持 PRoot 存活。
2. **任务管理层**：App 级管理器持有任务，独立于聊天生成和页面协程；任务记录及待投递结果持久化，日志置于不会被 rootfs 临时目录清理的应用目录。
3. **工具与聊天层**：`workspace_shell` 增加后台参数；增加列任务、读输出/等待、停止任务工具。后台完成通过 ChatService 回到所属会话。
4. **界面与 Android 服务层**：任务卡片、会话任务入口、日志界面、逐个停止/停止本会话全部任务；独立前台服务保持任务运行，不能随聊天生成结束一起释放。

工具面建议固定为 `workspace_shell(background?, timeout?)`、`workspace_task_list`、`workspace_task_output(taskId, cursor?, wait?)`、`workspace_task_stop(taskId)`。后台启动沿用现有 shell 审批；运行中转后台属于同一次已获准执行，不再重复启动或审批。模型的任务查询、读日志和停止限制在所属会话，不能凭另一个会话的 taskId 跨会话操作。

任务至少记录：taskId、conversationId、来源消息/分支、workspaceId、启动 cwd、命令、状态、开始/结束时间、退出码/信号、日志信息、完成事件标识及投递状态。运行状态与前台/后台标记分开，避免把“后台”误当执行结果。

执行中断、启动失败、取消和正常完成必须只落一个最终结果。进程创建期间被取消时，后来创建成功的进程也要被清理，不能泄漏。

### 3.4 清理与结果投递

- 当前 shell 超时仅强杀启动的进程，不能据此假定所有子进程都已退出。移植进程组/会话清理，先 TERM、三秒后 KILL，等待回收并关闭流和采集任务。
- 不假设 `ProcessBuilder` 返回的 PID 就是进程组 ID；进程适配须明确创建、持有并验证进程组/会话标识，防止 PID 复用后误杀。
- 复用现有 `terminal/src/main/cpp/termux_pty.cpp` 和 `LocalPtyTransport` 的已实现机制；非交互命令保持自身输入输出语义，不能仅为获取 PID 就强行混入交互终端。
- 单独验证主动创建新会话的后代及 PRoot tracee 清理边界，不宣称等同于容器隔离。
- 日志最终写入完成后，再发布终态和完成通知；运行中按游标读取，禁止反复返回全部日志。
- 对照上游持久化完成事件/确认机制，以稳定事件 ID 去重；崩溃后允许重试投递，不能重复插入同一完成结果。已完成未投递的结果补送，遗留运行命令标为中断。
- 完成事件通过 ChatService 和 `ConversationSession.update { latest -> ... }` / `flush()` 更新，不保存旧 Conversation 快照。已删除会话、无关消息分支和用户暂停状态都要重新检查。
- Android 前台服务类型按实际任务用途和当前 targetSdk 37 核实，处理启动失败、系统超时及用户停止，不能仅复制桌面端常驻逻辑。

### 3.5 聊天内任务 UI（最终确认）

- 原生聊天页右上角新增第三个任务按钮，角标以蓝色表示进行中、绿色表示全部结束、灰色表示无任务；任务列表默认收起，不占用消息区或输入框高度。
- 点击按钮从右侧展开不透明的 Material 3 抽屉，沿用当前主题配色和圆角；列表可滚动，支持关闭按钮、返回键、点击遮罩或滑动收起，打开时收起键盘。
- 卡片显示命令、启动/运行/停止中/完成/失败/超时/中断状态、前后台标记及用时；可查看日志、手动转后台、逐个停止；多个运行任务时提供全部停止。
- 抽屉同时展示进行中和已结束任务；点击日志打开沿用原有样式的底部详情，可切换实时尾部输出或按游标从头分页读取。已有 shell 工具消息也关联到最新任务状态。
- Web 聊天同步提供卡片、日志与停止，通过 SSE 更新状态；切换会话时关闭旧订阅并清空旧状态。

## 4. 任务二：任意附件统一上传，图片同时支持视觉与文件处理

### 4.1 当前已确认的断点

- Android `ChatAttachmentPicker` 使用 `isAllowedFileType` 白名单；Web `detectUploadFile` 也拒绝 ZIP 等二进制格式。
- 图片已经由 FilesManager 保存到应用 `upload` 目录，并映射到本地 rootfs `/upload`；缺少的是发给模型的“图片与实际文件路径”的对应信息。
- `DocumentAsPromptTransformer` 只为 Document 注入路径，其他格式最终可能落到 `file.readText()`，不能在允许任意文件后继续这样处理二进制。
- Android 外部分享进入聊天时，只转成图片、视频、音频消息，普通附件缺少兜底，部分失败时也需要保持源文件和 MIME 的对应关系。

### 4.2 最终行为

| 附件 | 本地保留 | 发给模型 |
| --- | --- | --- |
| 图片 | 上传后的实际文件保存在 `/upload/<唯一文件名>` | 保留视觉图片输入，并附同一张图片的明确路径、名称等信息 |
| 已支持提取的 PDF、DOCX、PPTX、EPUB | 保留原始文件 | 沿用已有提取能力，同时提供可访问路径 |
| 文本、代码、配置文件 | 保留原始文件 | 按可识别的文本处理，提供内容和路径 |
| ZIP、7z、其他二进制及未知格式 | 原样保存，允许加入聊天 | 仅提供名称、类型、大小、路径；由 Agent 使用工作区工具读取或处理 |
| 音视频 | 保留已有上传文件 | 保持现有模型能力处理，并在本地工作区可用时附文件路径 |

图片“双份”指视觉请求中的图片内容加本地持久文件，不要求再复制两份本地文件。现有 `/upload` 是共享挂载目录，不改成给每个本地工作区重复复制一份。

“任意文件”指取消类型白名单，不表示取消大小限制。先保留既有入口的大小策略，例如 Web 当前单文件 20 MiB；超限时返回明确错误。

### 4.3 实现步骤

1. 统一附件导入和分类：复用 FilesManager 与现有 MIME/文件头识别，覆盖文件选择、图片选择、相机、粘贴、画板、系统分享、Web 上传；避免重复复制已托管附件。
2. Android 和 Web 移除以文件类型决定能否上传的限制。MIME 用于选择消息表达方式；未知二进制使用 `application/octet-stream`，不能默认伪装成文本。通过“文件”入口选图片，也要保留图片视觉输入。
3. 所有成功导入的附件先落盘、登记 ManagedFile，再加入消息。文件名继续唯一化；原始名称与实际 `/upload/...` 路径保持可追踪对应，同名文件不覆盖。
4. 在输入转换阶段为本地附件添加稳定的文件描述，并让每张图片与其路径明确关联；不把所有路径混成无法对应图片顺序的一段文字。使用可安全表达文件名、空格和中文的格式。
5. 保留 Image part；补充路径的处理须兼容 OCR、模型视觉能力、历史消息和上下文压缩。非视觉模型仍沿用原有 OCR 行为，文件路径继续可供工具处理。
6. 将“支持上传”与“支持提取正文”分开。仅由现有专用解析器处理支持的文档；其他二进制不走 `readText()`，不把乱码或完整二进制塞进模型上下文。未识别格式保留元信息与原文件。
7. 仅在绑定、就绪的本地 rootfs 确实能访问时宣告 `/upload` 可用；无工作区或 SSH 场景保留附件及原有视觉/文档能力，不虚构远端文件路径。
8. 延续现有附件移除和消息编辑的引用清理规则，部分导入失败不得让文件内容、MIME、名称错配；浏览器客户端与 Android 的消息结果一致。

### 4.4 预计涉及位置

- `app/.../ui/components/ai/ChatAttachmentPicker.kt`、`ChatInput.kt`、`ui/pages/chat/ChatPage.kt`。
- `app/.../data/files/FilesManager.kt`、`FileUtils.kt`、原有文件类型判断及相应测试。
- `DocumentAsPromptTransformer.kt` 或其共享附件描述逻辑、`ChatRequestFactory.kt`；必要时补上下文中附件路径的保留规则。
- `web-ui/app/components/input/chat-input.tsx`、附件状态与消息转换，及服务端上传路由的已有错误处理。

## 5. 两个任务之间的关联

- 聊天生成结束、页面关闭或任务转后台时，不删除已上传附件。
- 后台任务运行期间保护所属会话的附件引用；消息删除触发的自动物理回收可以延后至任务结束，避免正在处理的输入文件突然消失。
- 删除会话/工作区须先停止并等待相关任务清理，之后再释放附件引用和磁盘文件；任务完成回调不得重新插入已删除会话。
- 上传目录保留已有“读取原件、修改前复制到 `/workspace`”的使用约定；任务产物写工作区，继续使用现有文件展示和导出能力。

## 6. 实施顺序与验收

按独立改动交付，便于逐项审查：

1. **附件链路**：统一导入、放开类型、图片路径、二进制处理，先验证所有入口。
2. **任务执行核心**：受管理进程、任务归属、前后台转换、有界日志、停止和持久化。
3. **生命周期与聊天集成**：前台服务、结果队列、用户暂停、重启对账、删除前清理。
4. **界面与联合验收**：任务卡片/管理/日志、Android/Web 一致性、附件与后台任务联动。

### 自动化验收重点

- 上传 ZIP、7z、未知后缀、中文名称、同名文件、图片、空文件及超限文件，各入口得到一致且可理解的结果。
- 图片视觉 part 与 `/upload` 路径同时存在；多张图片对应正确；非视觉模型和历史上下文仍可定位附件。
- 压缩包和其他二进制不被当文本读取；已有 PDF/文本提取不回退；系统分享普通文件不丢失。
- 前台转后台只启动一次；工具返回/生成结束不取消后台任务；超时与等待时限分离。
- 启动期间取消、快速静默退出、非零退出、输出超限、并发超限、完成与取消竞速均能正确收尾。
- 停止清理会话成员和输出采集任务；完成后才公布完整最终日志；日志游标不重复输出已有内容。
- 后台结果只入队一次；用户停止后不自动恢复生成；会话/分支切换及删除不会错投或复活数据。
- 重启后运行记录转中断，已完成未投递结果可补送；Room 迁移和旧数据兼容。
- 任务运行中附件仍可读，删除会话/重装 rootfs 时先完成任务清理。

对照移植上游已有竞态和清理测试，新增测试聚焦本项目行为，不堆砌只复述实现的用例。执行相关模块 JVM 测试（`app`、`workspace`、`terminal`）、`assembleDebug`、适用的 Lint 与 `spotlessCheck`；Web 执行 `bun run typecheck`、`bun run fmt:check` 和生产构建。

### Android 设备验收

- 在真实 PRoot 环境运行长脚本、小型 HTTP 服务及有子进程的命令，验证转后台后可继续聊天、读日志、停止。
- 验证退到桌面、锁屏、通知操作、前台服务启动失败/超时及 App 被停止后的状态对账。
- 验证子进程主动创建新会话时的清理结果；没有设备实测结果时明确列为未验证，不用 JVM 测试替代结论。
