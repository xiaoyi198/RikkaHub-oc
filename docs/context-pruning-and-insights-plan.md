# 上下文裁剪稳定性与上下文洞察实施计划

日期：2026-10-23。状态：已实现；定向测试、Android 编译、格式及迁移检查通过，设备界面验收待进行。

执行调整：按用户要求，裁剪记录只使用消息 ID 与工具调用 ID，不新增哈希或指纹；测试收敛为必要的裁剪回归、迁移检查和编译验证。

调研基线：`cc23773c` 及当前工作区。现有 `ContextPruning.kt`、`ManagedContext.kt`、`SettingContextAdvancedPage.kt` 和两个上下文测试文件存在未提交修改，实施时在这些改动上继续，不覆盖或回退。

## 1. 目标与范围

本次采纳此前建议的前两项：持久化已裁剪决定、按新增可释放量触发批量裁剪；同时在 Android 聊天界面的二级菜单增加“上下文洞察”。

交付行为：

- 已裁剪的工具结果在后续模型步骤、新用户轮次、离开聊天及 App 重启后继续使用相同占位文本，原始消息和结果保持完整。
- 未达到下一批裁剪阈值时，只追加新内容，已有裁剪范围保持稳定。
- 用户可以查看上下文构成、最近一次请求的缓存用量、裁剪批次和当前分支的摘要，理解上下文被怎样处理。

边界：

- 沿用已有上下文压力下的 `ignoreMinimum` 行为，并让其决定持久化；不另改压缩触发水位、目标水位和默认预算。
- 不修改摘要请求的组装方式，不做同模型摘要前缀复用；该项留待后续。
- 首版面向 Android 聊天页，不扩展 Web UI，不增加新的模型工具。
- 不以达到某个固定命中率作为验收条件；客户端能保证请求投影的稳定性，缓存命中仍取决于服务端和实际新增输入。

## 3. 持久化裁剪决定

### 3.1 数据模型

新增独立的裁剪批次派生数据，不把占位文本写回原始 `UIMessage`。

建议模型：

- `ContextPruneEntry`：消息 ID、`toolCallId`、实际使用的占位文本、该结果的估算净释放量；不新增哈希、指纹或原文副本。
- `ContextPruneBatch`：稳定 ID、会话 ID、创建时间、触发原因（达到新增阈值／上下文压力）、本批 entries。
- 批次存储：复用现有上下文仓库，增加会话批次的加载、观察和插入接口，不额外引入一层仓库。

记录实际占位文本，保证升级实现后不会仅因文案版本改变而重写旧请求前缀。批次时间和内部 ID 只用于本地界面，不注入模型上下文。

新增 `context_prune_batch` 表，以会话外键级联删除，按 `conversation_id` 建索引，payload 序列化批次明细。当前数据库版本为 34，预计新增 34 → 35 迁移；实施前复核最终版本，更新 schema、数据库工厂及 DI 注册。

### 3.2 应用规则

1. 从当前分支的原始消息生成稳定的 source 范围。
2. 加载已有裁剪记录，按当前分支的消息 ID 和工具调用 ID 匹配记录。
3. 在摘要投影后，只替换仍以原始工具结果出现且来源匹配的部分；已被摘要覆盖的结果不再替换或重复计入当前节省量。
4. 最近两轮保护、保留结果预算仅用于决定新的候选；已生效记录不会因进入新用户轮次而自动恢复原文。
5. 记录只清除工具输出，保留调用参数及原有回查引用；详情回查读取本地原始结果。

分支与设置约定：

- 切换分支时只应用匹配记录，不删除其他分支的批次；切回原分支可继续复用。
- 追加 part 不影响先前工具调用的记录；普通消息编辑会创建新消息 ID，新分支自然不匹配旧记录，切回旧分支仍可复用。
- 关闭增强上下文、关闭裁剪或失去历史回查能力时，沿用现有开关语义，不应用裁剪；重新开启时验证并复用记录。
- 工具保护名单变更应明确排除新受保护工具的记录，允许这类用户主动配置变更产生一次前缀变化。
- 删除会话时一并清理批次；会话删除／替换期间的异步提交不得重建记录。

### 3.3 提交与并发

- 通过 `ChatService` 提交派生状态，参照 `persistContextSummary` 使用 session incarnation、当前选中分支验证和串行写入。
- 以消息 ID 与调用 ID 识别同一结果，避免同一结果在重试或重复 prepare 时产生多个有效条目。
- 来源匹配失败时重新读取最新会话状态，不把未经提交的裁剪计划发送给模型。
- 普通 UI 订阅只读仓库及 session 状态，不保存整份 Conversation，不覆盖数据库读取前的会话快照。

## 4. 按新增净释放量批量触发

将当前裁剪流程拆为：应用有效批次 → 规划新增候选 → 判断是否提交新批次。

```text
原始当前分支
  → 应用有效摘要与已有裁剪记录
  → 找出尚未裁剪且符合保护规则的工具结果
  → 累计新增净释放量（扣除占位文本开销）
  → 达到 minimum：提交新批次
  → 未达到 minimum：保持已有裁剪范围
  → 现有压力条件触发：允许提前提交，后续继续沿用
  → 使用已提交记录生成请求投影
```

- 保留现有最近两轮、新鲜工具批次、未执行／待审批工具、特殊保护工具和非纯文本结果的候选保护规则。
- 已提交记录不再参加新增 minimum 的累计，也不重复消耗候选保留预算。
- `ignoreMinimum` 只跳过新增批次的最小释放量，不跳过其他保护规则。
- 批次不可获得正的净释放量时不提交；相同输入重复 prepare 不产生新批次。
- 压缩使用未裁剪原文生成摘要的现有语义保持不变；摘要形成后，不恢复其他仍有效的裁剪记录。
- 状态提示改为本次新增裁剪数量／净释放量，避免每一步重复报告历史累计裁剪。

示例：minimum 为 20k 时，首次新增净释放 20k 提交一批；其后新增 3k、8k 均不改变已有范围，新增累计达到 20k 后再提交下一批。上下文压力提前提交的批次成为新的已提交基线。

## 5. 聊天页“上下文洞察”

### 5.1 入口与交互

- 入口固定为：聊天输入框的更多按钮 → 现有二级菜单 `FilesPicker` → “上下文洞察”。使用现有“查看上下文摘要”位置，不增加聊天顶栏按钮。
- 点击后收起菜单，打开独立、可滚动的 `ContextInsightsSheet`；由聊天页管理可见状态并按会话 ID 重置，避免叠加两个 ModalBottomSheet。
- 无需先开启增强上下文，也可查看已有真实用量；未配置模型、空对话、无 usage 时提供对应空态。
- 返回键先关闭洞察。保留上下文管理设置入口，不在洞察里增加裁剪、重置批次或压缩等写操作。
- 遵循 Material 3 Expressive：tonal 容器、强调标题、`CardGroup` 分段、整行展开点击，使用主题色和圆角；图标优先复用现有图标，新增名称时先查询 HugeIcons。
- 首版沿用仓库约定使用中文文案，不扩展多语言翻译范围。

### 5.2 展示内容

| 区域 | 用户看到的内容 | 数据口径 |
| --- | --- | --- |
| 最近一次聊天请求 | 请求时间／模型、实际输入 token、缓存命中 token、未命中 token、命中率 | 当前分支对应的最后一次请求 usage；使用 `lastRequestUsage()`，不使用多步累计 usage |
| 上下文构成 | 系统指令、工具定义、用户内容、助手文字／推理、工具结果、摘要、附件的占用分布 | 已组装请求的本地估算；各部分互斥，不重复计算 |
| 预算 | 模型窗口、可用输入预算、输出预留、触发阈值及目标值 | 会话当前配置，通过 `getAssistantOf`／`getChatModelOf` 解析 |
| 工具裁剪 | 当前生效的结果数量、估算净释放量、各批次时间和原因 | 仅当前分支有效且未被摘要覆盖的记录；可展开查看工具名称及本地原始结果 |
| 下一批裁剪 | 当前新增候选的净释放估算／minimum、保护范围说明 | 只读规划结果，不因此提交计划；无可靠候选快照时不显示进度 |
| 历史摘要 | 当前分支生效摘要、来源消息范围、摘要前后估算和可展开正文 | 复用原 `ContextSummarySheet` 的来源匹配和内容展示 |

实际用量与估算分开标注：

- 命中率为 `cachedTokens / promptTokens`；输入为零显示“暂无数据”，缺失 usage 不展示为 0%。
- 最近一次请求始终注明是历史实际值，不把它标成下一次请求占用；输出 token 不混入输入占用。
- 构成图只展示同一估算口径的分布，不强行缩放到服务端实际 token 总数。
- 原始 token、裁剪节省和摘要节省分别展示，不将重叠范围的节省量相加。
- UI 说明“本地内容发生裁剪／压缩”与实际命中率，不推断服务端缓存淘汰原因，不把当前分支占用混同于会话所有分支历史。

### 5.3 只读数据链路

- 在正常请求准备完成时生成轻量 `ContextInspectionSnapshot`：会话／当前分支标识、配置快照、请求步骤标识、模型、估算分布、裁剪概况、候选量和时间。
- 快照对应最终实际使用的 `StepRequest`，通过 session 的 StateFlow 发布；同一步的 usage 到达后再关联，重试或迟到回调不能覆盖别的步骤。
- 打开面板只订阅 session、已有消息 usage、裁剪批次与摘要。禁止调用 `ManagedContext.prepare()`、输入转换流水线、历史索引、模型接口或工具执行，以免查看本身改变上下文或产生网络请求。
- 仅有历史消息或 App 重启后，仍可读取原有 usage、摘要和持久化批次；若缺少对应的请求构成快照，显示“本次打开后尚无请求构成数据”，不伪造完整请求估算。
- 切换分支、模型／配置改变后，不把旧快照呈现为新配置的当前状态；最近一次实际请求可作为明确标注的历史数据保留。
- 不持久化完整 API 请求或另一份对话原文；明细通过稳定来源引用读取，避免重复存储大工具输出。
- `ChatVM` 暴露请求快照，面板只读订阅上下文仓库；流式输出不逐 token 扫描全历史，只在请求步骤、批次或摘要变化时更新。
